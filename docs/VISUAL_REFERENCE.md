# Noetic: visual reference

One page of diagrams for what Noetic is, how a request flows through it, what it can do today, what it deliberately will not do, and what is still missing.

Every capability below was checked against the code or by running it (see [How this was verified](#7-how-this-was-verified)). `tests/test_visual_reference.py` fails if a CLI command, MCP tool or pipeline is added without being listed here.

Related: [HOW_TO_USE](HOW_TO_USE.md) (steps), [ARCHITECTURE](../ARCHITECTURE.md) (internals), [ROADMAP](../ROADMAP.md) (status).

## 3. How one request flows

Example: `noetic run curate "agent memory"`

```
  you ──▶ noetic run curate "agent memory"
            │
            ▼
   1  build context (knowledge)      budgeted; private folders never read
            │
            ▼
   2  render prompt (tools)          contract + preamble + your interests + prompt file
            │
            ▼
   3  pick agent                     steps.curate → agents list → first installed
            │                                  ▲
            ▼                                  │ quota / auth / not installed
   4  run agent CLI ──────────────────────────┘ (fallback to next agent)
            │
            ▼
   5  validate: JSON schema + extra checks ──✗──▶ retry ONCE with exact errors
            │ ✓                                          │ ✗ again
            ▼                                            ▼
   6  Python writes the note                        run stops, compact error
      status: pending_review                        `noetic run resume <id>`
            │                                       (finished steps are reused)
            ▼
   7  YOU read it ──▶ noetic approve <file>      (or reject --reason)
```

The agent is a step, not a planner. Python owns the flow.

## 5. What it will NOT do (by design)

```
  ┌─────────────────────────────────────────────────────────────────────┐
  │ ✘ Post to X/Twitter or any external service     you post by hand    │
  │ ✘ Mark anything `curated` for you               taste is yours      │
  │ ✘ Commit or push in repos it works on           you review the diff │
  │ ✘ Read your private folders or private profile  private_paths       │
  │ ✘ Delete or move your inbox notes               librarian only reads│
  │ ✘ Overwrite your text in CLAUDE.md etc.         only marked blocks  │
  │ ✘ Overwrite other servers in an MCP client file malformed = skipped │
  │ ✘ Install a scheduled task by itself            prints the command  │
  │ ✘ Let an agent plan open-endedly                fixed steps only    │
  └─────────────────────────────────────────────────────────────────────┘
```

## 6. What it CANNOT do yet, and what it SHOULD do next

```
 GAP (verified)                                         WHY IT MATTERS            PRIORITY
 ─────────────────────────────────────────────────────────────────────────────────────────
 Not on PyPI; CI never run on GitHub                     uvx / pipx paths need it   1 (manual
                                                                                      step: yours)
 No process sandbox. Policy gate is a denylist           don't run untrusted code   —  documented
 sanitize_input exists but pipelines do not call it      prompt-injection hardening 2
 Eval baseline is rule-based, held-out F1 0.75           no real LLM extractor graded 3
 delegate never run against a real agent CLI             only mock-tested           2
 clip / think / focus / web (Phase 1) live in the vault   not in the public package  3  decide:
  harness, not in `noetic-cli`                                                    port or keep private
 Zen web view does not show repo telemetry               dashboard lags the CLI     4
 `noetic://quests` resource is legacy                  quest/XP system is retired 3  remove
 gemini adapter: CLI no longer works for personal        stale for most users       4
  Google accounts (kept for API-key users)
 Windows-only paths were exercised; Linux/macOS          claims untested there      2  CI will cover
  covered only by CI that has not run yet
 No `noetic init` guided first run                     first 5 minutes are manual 3
 Librarian does not extract frameworks                   that stays with /ingest    —  by design
```

Reading the priority: 1 = blocks the public release, 2 = correctness or trust, 3 = cleanup, 4 = nice to have.
