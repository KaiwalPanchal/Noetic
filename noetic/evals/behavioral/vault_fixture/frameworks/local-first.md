# Framework: Local-First Software

**Source:** Local-first software: You own your data, in spite of the cloud — Martin Kleppmann et al. (https://www.inkandswitch.com/local-first/)  
**Linked Interests:** [[interests#offline-first]], [[interests#user-agency]], [[interests#longevity]]

**Admission Score:** 5.0/5.0 (Admission Rubric)

## 1. Core Idea
Software should store primary data on local client devices and use cloud infrastructure solely as replication relays.

## 2. Core Heuristic & Trigger
- **When in architecting client-server synchronization and storage** → Prioritize **Local storage as primary copy and CRDTs for convergence** over _Centralized database as single source of truth_ because local-first guarantees continuous offline availability and perpetual user data ownership. (Rule: `Local disk is primary truth; cloud servers are ephemeral replication relays`) [Tier 2] [Tags: distributed-systems, architecture] [Anchor: You retain ultimate ownership and control. The user's device holds the authoritative, primary copy of data; cloud servers act strictly as replication relays and archival backups, never as the single source of truth.]
- **When in designing multi-user state convergence** → Prioritize **Deterministic CRDT conflict resolution** over _Centralized pessimistic locking_ because pessimistic locks stall during network partitions and destroy mobile offline capability. (Rule: `Model document mutations as commutative event deltas or state-based CRDTs`) [Tier 2] [Tags: distributed-systems, concurrency] [Anchor: To achieve seamless multi-master collaboration without centralized write arbiters, local-first architectures employ Conflict-free Replicated Data Types (CRDTs).]
- **The Core Question / Razor:** "Can the user execute all essential workflows indefinitely without network access?"
- **Governing Invariant:** User device holds primary truth; server is an ephemeral replication relay.

## 3. Mental Moves / Procedures
1. Establish local disk persistence as primary data layer.
2. Implement offline read/write queues.
3. Integrate CRDTs for multi-peer state convergence.
4. Treat remote servers as untrusted or optional sync relays.

## 4. Where to Apply
- **Primary Domain:** distributed-systems
### Ontology Primitives
- **Local Storage Primary Copy** (`state`): The authoritative dataset residing directly on user hardware.
- **CRDT** (`entity`): Conflict-free Replicated Data Type ensuring deterministic convergence.
- **Replication Relay** (`entity`): Cloud server functioning solely to forward sync packets between peers.

### Trade-Off Matrix
| Tension Dimension | Recommended Choice | Sacrificed | Gained | Boundary Flip Condition |
| :--- | :--- | :--- | :--- | :--- |
| Storage & Sync | Client primary storage with CRDT convergence | Simple centralized ACID relational transactions | Sub-millisecond local interaction latency, 100% offline availability, 30-year data longevity | High-frequency global inventory reservation where double-allocation causes immediate financial loss (e.g. airline seat reservation) |

## 5. Anti-Patterns & Boundaries (When it Breaks)
- **Cloud Spinner Trap**: Disabling user input or blocking UI interactions while awaiting server HTTP response → App becomes completely unusable in airplanes, subways, or flaky mobile connections (Recovery: Make UI optimistic, write to local SQLite immediately, and sync in background)
